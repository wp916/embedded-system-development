# Embedded System Development Skill

面向复杂机器人与嵌入式控制系统的工程生成 Skill。

本 Skill 通过自然语言需求，规划并生成基于 **STM32CubeMX、STM32 HAL 和 FreeRTOS** 的完整嵌入式工程。它不仅生成业务代码，还保留 `.ioc`、CMSIS、HAL、中间件及工具链工程文件，确保项目可继续配置、编译、下载和调试。

## 核心功能

- 保持 CubeMX 原生工程结构和再生成兼容性；
- 采用固定分层与清晰接口，隔离硬件、通信和业务逻辑；
- 明确任务、队列、中断、DMA、回调及缓冲区所有权；
- 提供配置说明、风险项、调试步骤和测试代码；
- 支持电机控制、传感器采集、多总线通信、状态机及多任务实时控制等复杂系统。

目标是让 Agent 生成的代码具备实际开发与上板调试的可行性。随着工程规模增长，仍能依据模块边界、数据流和故障路径快速定位问题，避免依赖混乱和修改失控。

## 五层逻辑架构

五层代表职责与依赖关系，不要求建立同名顶层目录，也不会替代 CubeMX 原生结构。依赖原则上由上向下，底层不得反向依赖具体业务。

1. **官方底层库（Platform）**  
   负责启动文件、CMSIS、HAL、时钟、GPIO、中断、DMA 和外设初始化。仅提供芯片及板级基础能力，不包含设备业务和控制策略。

2. **实时操作系统层（RTOS）**  
   负责任务、队列、通知、同步、软件定时器及内存配置。仅提供调度与并发机制，不实现器件协议和机器人业务。

3. **通信增强层（Comms）**  
   在 HAL 接口之上实现非阻塞收发、发送排队、数据分发、超时和错误诊断。负责数据可靠传输，不解释设备业务含义。

4. **硬件驱动层（Drivers）**  
   封装传感器、电机和执行器，提供初始化、控制、状态读取、回调及错误接口。负责单个器件，不编排整机流程。

5. **应用层（App）**  
   组合硬件实例，实现状态机、控制回路、安全策略、命令处理和任务编排。通过下层公开接口使用硬件，不直接访问 HAL、LL 或寄存器。

## 使用方法

1. **描述需求**  
   用自然语言说明系统功能、硬件、通信方式、实时性和验收条件，并尽量提供原理图、引脚表、协议、器件手册或已有工程。Agent 会通过多轮沟通整理需求，对关键缺失信息进行询问，并给出常见配置建议。

2. **确认 CubeMX 模板**  
   Agent 根据 MCU、时钟、引脚、外设、DMA、中断、FreeRTOS 和工具链创建 CubeMX 工程文件。你可以检查和调整 `.ioc`，确认硬件结构与资源分配后再继续,由CubeMX创建基本工程模板。

3. **生成完整工程**  
   Agent 按五层架构生成模块、接口、任务、数据流和错误处理代码。遇到影响正确性的未知信息时，会暂停相关实现并向你确认。

4. **逐层调试**  
   Agent 提供测试代码和调试建议，依次验证底层外设、RTOS、通信、硬件驱动和应用逻辑，帮助系统稳步完成联调。未经过目标硬件测试的结果会明确标记为待上板验证。

建议首次交流时说明 MCU 与板卡型号、器件清单、接口协议、引脚及外设约束、任务周期、开发工具版本、系统流程和验收标准。
